# Relay Work UI 가이드

## 목적

Relay Work는 소규모 팀이 메신저에서 놓치기 쉬운 공지와 요청을 한곳에서 확인하고 처리하도록 돕는 서비스다. UI는 복잡한 프로젝트 관리 도구가 아니라, **전달사항을 빠르게 확인하고 읽음·완료 상태를 구분하는 팀 인박스**를 목표로 한다.

## 반응형 구조

| 화면 크기 | 구조 |
| --- | --- |
| 모바일 | 상단 컨텍스트 + 단일 열 콘텐츠 + 하단 내비게이션 |
| 태블릿 | 넓어진 단일 열 또는 카드 2열 |
| 데스크톱 | 좌측 고정 내비게이션 + 넓은 본문; 홈은 본문/보조 패널 2열 |

모바일에서 먼저 정보 우선순위를 정하고, 데스크톱에서는 같은 정보 구조를 더 넓게 확장한다. 기능이나 데이터 구조를 화면 크기에 따라 다르게 만들지 않는다.

## 색상과 상태

- 기본 행동: 블루 — 작성, 이동, 선택된 내비게이션
- 중요: 앰버 — 중요한 전달사항
- 미완료·위험 동작: 로즈/레드 — 완료가 필요한 요청, 삭제
- 완료: 그린 — 처리 완료 상태
- 일반 정보: 슬레이트 — 보조 텍스트·테두리·비활성 상태

색은 장식보다 상태 전달에 우선 사용한다. 상태는 색만으로 표현하지 않고 아이콘과 텍스트를 함께 제공한다.

## 화면 목록

| 경로 | 화면 | 주요 목적 |
| --- | --- | --- |
| `/teams` | 팀 선택 | 참여 중인 팀 진입 또는 새 팀 생성 |
| `/teams/new` | 팀 생성 | 팀 이름·설명 입력 |
| `/` | 팀 홈 | 미읽음·중요·미완료 요약과 최신 전달사항 확인 |
| `/items` | 전달사항 목록 | 검색·필터·목록 탐색 |
| `/items/[id]` | 전달사항 상세 | 내용 확인, 읽음/완료 상태 확인 |
| `/items/new` | 전달사항 작성 | 대상·중요·완료 관리가 포함된 전달사항 등록 |
| `/items/[id]/edit` | 전달사항 수정 | 기존 전달사항 수정 또는 삭제 진입 |
| `/members` | 팀원 관리 | 팀원과 역할 확인 |
| `/settings` | 팀 설정 | 팀 정보·카테고리·역할 관리 진입 |
| `/preview` | UI 데이터 프리뷰 | API 응답과 상태별 UI를 종합 검토 |

## 상태 디자인

모든 데이터 화면에는 아래 상태를 준비한다.

1. 로딩: 기존 레이아웃 크기를 유지하는 스켈레톤
2. 성공: 데이터의 중요도와 최신성을 우선해 표시
3. 빈 상태: 이유를 설명하고 다음 행동 CTA 제공
4. 오류: 문제 설명과 재시도 행동 제공
5. 권한 없음: 팀 관리자 문의 등 사용자가 취할 수 있는 다음 행동 제시

## 접근성 기준

- 모든 클릭 대상은 모바일에서 충분한 터치 크기를 유지한다.
- 키보드 포커스가 보이는 입력·버튼 스타일을 제공한다.
- 아이콘만으로 의미를 전달하지 않는다.
- 삭제 같은 되돌릴 수 없는 행동은 확인 다이얼로그를 거친다.
- 작은 화면에서 수평 스크롤이 필요한 필터는 한 줄 칩 영역으로 제한한다.

## 디자인 QA

`/preview`에서 성공·빈 결과·오류 응답 예시와 UI 표현을 함께 확인한다. 실제 API를 연결할 때는 `docs/API.md`의 응답 형식과 이 화면의 목업을 비교해 상태별 표현이 빠지지 않았는지 검토한다.
