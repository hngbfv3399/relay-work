# 백엔드 구현 보고서

기준: 2026-08-15, `프로젝트 2 - 개발 계획`과 `1일차` 기록.

## 완료

- NestJS API, Prisma, SQLite, health check, 데모 사용자 생성·인증
- 팀·멤버·역할·카테고리 관리와 역할 기반 권한 검사
- 전달사항 생성·목록·상세·수정·완전 삭제
- 팀 전체/특정 멤버/특정 역할 대상 공개 규칙 및 자동 읽음 기록
- 완료 상태, 홈 통계, 커서 페이지네이션
- 목록 검색: 카테고리·중요도·미읽음·완료 상태·키워드·기간
- 공통 Zod 계약을 `packages/contracts`로 이동
- 반복 실행 가능한 시드 데이터와 프론트용 API 명세

## 기획과 다른 확정 사항

- 데이터베이스는 MVP 범위에 맞춰 Docker/PostgreSQL 대신 SQLite를 사용한다.
- 초기 계획의 담당자와 `TODO/IN_PROGRESS/DONE` 대신, 최신 기획 기록의 “담당자 없음 / 완료 관리 선택 / INCOMPLETE·COMPLETE” 규칙을 적용한다.
- 전달사항은 요청 시 완전 삭제하며 복구 기능은 제공하지 않는다.

## 프론트 전달물

- API 경로·요청·응답·필터: `docs/API.md`
- 공통 요청 계약: `packages/contracts/src/index.ts`
- 시연 데이터: `apps/api/prisma/seed.mjs`

## 새 사용자와 팀 생성

- 새 사용자는 `POST /auth/demo-users`로 본인의 데모 사용자 ID를 받는다.
- 그 ID를 `x-demo-user-id` 헤더로 넣어 `POST /teams`를 호출한다.
- 생성 호출자만 해당 팀의 OWNER로 저장된다. 이후 팀 접근과 권한은 이 ID를 기준으로 구분된다.
