# 개발 범위와 진행 원칙

## 목표

최대 2주 안에 Relay Work MVP를 시연 가능한 수준으로 완성한다. 사용자는 프론트엔드 구현과 UI 구조 이해를 중심으로 작업하며, 반복적이거나 기반 작업은 AI 보조를 활용한다.

## 우선순위

### 반드시 완료

- 팀 선택과 팀 생성
- 팀 홈 현황
- 전달사항 목록, 상세, 작성, 수정
- 읽음·완료·중요·대상 상태 표시
- 검색과 기본 필터
- 팀원·카테고리·역할 관리 UI
- 모바일/데스크톱 반응형 및 빈·로딩·오류 상태

### 시간 여유가 있을 때

- 실제 팀원 초대 흐름
- 카테고리/역할 생성·수정의 세부 모달
- 다크 모드 완성도 개선
- E2E 테스트와 배포 환경 정리

### MVP 이후

- 실제 인증·초대
- 파일 첨부
- 실시간 알림
- 팀 삭제 및 데이터 보존 정책

## 역할 분담 원칙

- 프론트엔드: 화면 구조, UX 판단, API 연동 확인, UI 품질 검토
- AI 보조: 반복 UI 구현, 초기 API/데이터 기반 코드, 문서 초안, 테스트 보조
- 최종 판단: 요구사항과 UX 결정, 코드 검토, 배포 책임은 프로젝트 작성자가 가진다.

AI를 활용한 부분도 결과물을 이해·검토하고 수정 가능한 상태로 유지한다. 이 문서는 기여도를 과장하거나 축소하기 위한 것이 아니라, 짧은 개발 기간에서 작업 방식을 투명하게 기록하기 위한 것이다.

## 권장 작업 순서

1. `docs/API.md`를 기준으로 프론트 API 클라이언트와 사용자 식별을 연결한다.
2. 팀 선택 → 팀 홈 → 전달사항 목록/상세 순서로 실제 데이터를 연결한다.
3. 작성·수정 후 홈/목록의 캐시 갱신을 연결한다.
4. 권한·빈·로딩·오류 상태를 실제 응답으로 검증한다.
5. 모바일과 데스크톱에서 UI를 점검하고 시연 시나리오를 작성한다.

## 커밋 가이드

기능 단위로 작고 명확하게 커밋한다.

```text
feat(web): connect team home to API
feat(web): add item creation flow
fix(web): handle empty item list
docs: document UI states and MVP scope
```

커밋 작성자는 저장소 소유자 계정을 사용한다. AI 보조 사실은 필요하면 README 또는 이 문서에 짧게 명시하되, 실제로 검토하지 않은 변경을 자신의 작업으로 설명하지 않는다.
